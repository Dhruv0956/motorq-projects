ACE Weed/Crop Rover Model - Experiment Map And Next Plan
=========================================================

Date: 2026-05-24
Scope: Planning and context consolidation only. No training, export, file cleanup, or dataset mutation was performed for this plan.


1. Current Aim
--------------

Build a high-accuracy local model pipeline for Jetson Nano that can:
- Read rover camera frames.
- Detect crop/weed regions with bounding boxes.
- Identify weed species for the most important species.
- Run locally on the Jetson Nano without network calls.

Current preferred architecture:
- Stage 1: YOLO detector for field localization.
- Stage 2: classifier for species identification on cropped weed detections.

This is the right direction. Detection and fine-grained species recognition are different problems, and separating them reduces confusion during training and evaluation.

4. Key Findings
---------------

4.1 The two-stage plan is correct.

Best structure:
- Detector finds weeds/plants in rover frames.
- Classifier identifies weed species on cropped detections.

This prevents the classifier from needing to solve localization and prevents the detector from needing to learn fine-grained species differences too early.


4.2 Current Top5 species selection may be wrong for rover field deployment.

Current Top5_Weeds_Dataset:
- Lavhala
- Bilayat
- Gajar_Gavat
- Harali
- Punarnava

Field annotation top 5:
- Lavhala
- Lamber_Quarter
- Kena
- Obscure_morning_glory
- Little_Mallow

Decision needed:
- If the final rover must identify the most common field species, use the field top 5.
- If the user specifically needs the current named species for agronomic reasons, keep them, but understand some are rare/absent in field labels.


4.3 Crop detection is not yet solved by MH-16.

The MH-16 field config lists weed species, not crop.

Open question:
- Are crop boxes present in any MH-16 labels?
- If not, Stage 1 can detect weeds, but it cannot properly detect crop boxes unless a crop-labeled dataset is added.


4.4 Some scripts are useful but risky.

Useful:
- train_stage1_binary.py: trains field detector with all species collapsed to weed.
- validate_stage1.py: safe validation pass for train13.
- build_dataset.py: generated Top5 full-frame dataset.
- create_field_links.py: builds symlinked field dataset.

Risky:
- clean_corrupt_boxes.py rewrites labels inside Field_Binary_Dataset.
- Because those labels are symlinks, rewriting may modify raw annotation files on Desktop.
- Do not run it again until this behavior is made safe by copying labels instead of writing through symlinks.


5. Recommended Architecture
---------------------------

Stage 1 Detector:
- Goal: localize field weeds, and crop only if crop labels exist.
- Starting model: YOLOv8n or YOLO11n.
- Input size: 640 for accuracy first.
- Training dataset: Field_Binary_Dataset.
- Class mode:
  - Option A: single_cls=True for one "weed" class, simplest and robust.
  - Option B: multi-class field detector for top 5 species directly, only after Stage 1 single-class quality is proven.

Stage 2 Species Classifier:
- Goal: classify cropped weed detections into 5 species.
- Starting model: YOLO classification nano/small or MobileNet/EfficientNet-lite style classifier.
- Training data:
  - Best: crops extracted from Field_Binary_Dataset boxes for selected species.
  - Backup: Top5_Weeds_Dataset individual species images.
- Output:
  - species name
  - classifier confidence

Pipeline:
- Capture frame from rover camera.
- Run Stage 1 detector.
- For each weed detection, crop the box with padding.
- Run Stage 2 classifier on the crop.
- Draw box and label:
  - weed species if classifier confidence is high
  - weed_unknown if classifier confidence is low
  - crop only if crop detector exists


6. Next Execution Plan
----------------------

Step 1: Freeze current artifacts.
- Do not delete any runs.
- Treat train8, train13, weed_crop5, and weed_crop2 as reference points.
- Start naming future runs explicitly instead of relying on train14/train15 auto names.

Step 2: Validate train13 safely.
- Run a validation-only pass on train13 best.pt using configs/dataset_stage1.yaml.
- Use low batch and workers=0.
- This tells whether train13 is a real Stage 1 detector candidate.

Step 3: Decide the target five species.
- Recommended if optimizing for field frequency:
  - Lavhala
  - Lamber_Quarter
  - Kena
  - Obscure_morning_glory
  - Little_Mallow
- Alternative if agronomic requirement overrides frequency:
  - Keep current Top5 list, but expect lower field performance for rare species.

Step 4: Build a classifier dataset from field crops.
- For selected five species, crop boxes from Field_Binary_Dataset images.
- Save classifier folders:
  - datasets/Field_Top5_Classifier/train/<species_name>/
  - datasets/Field_Top5_Classifier/val/<species_name>/
- Add padding around boxes so leaves are not clipped.
- Keep a low-confidence/unknown policy for deployment.

Step 5: Train Stage 2 classifier.
- Start small.
- Prioritize per-class recall and confusion matrix.
- Do not judge it only by global accuracy because class imbalance is large.

Step 6: Re-train or keep Stage 1 detector based on validation.
- If train13 validates well, keep it as Stage 1 candidate.
- If train13 is weak, retrain Stage 1 from a clean YOLO nano model with:
  - single_cls=True
  - imgsz=640
  - cache=False
  - workers=0 or 2
  - explicit run name

Step 7: Integrate detector + classifier locally.
- Create an inference script that accepts:
  - detector weights
  - classifier weights
  - camera/video source
  - FPS throttle
- Output annotated frames with species names.

Step 8: Jetson Nano deployment.
- Export detector to TensorRT FP16.
- Export classifier to TensorRT FP16.
- Benchmark on Jetson Nano at target camera resolution.
- If FPS is below target, reduce detector imgsz before reducing classifier quality.
