Iteration 001 - Project Scaffold For Local Edge Detection
Date: 2026-05-17

What was done:
- Created an initial project scaffold for a local weed/crop object detector.
- Added README.md with the target architecture and operating assumptions.
- Added configs/weed_crop.yaml for YOLO-format dataset configuration.
- Added requirements.txt with core dependencies.
- Added scripts/train_export.py for training and exporting models.
- Added scripts/detect_local.py for local camera/video/image inference throttled to 1 FPS.
- Added .gitignore to keep datasets, runs, and model artifacts out of source tracking by default.

Why it was done:
- The workspace initially only contained Git metadata and no implementation files.
- The requirement was to detect weeds and plants with bounding boxes locally on edge hardware, without a network call.
- A minimal YOLO detector pipeline was the quickest practical path to a small, low-latency edge model.

Thought process and reasoning:
- Chose a nano YOLO-style detector as the baseline because it balances bounding-box accuracy, small model size, and edge deployment support.
- Set the initial input size to 320 because the target requirement is only 1 FPS and the user prioritized minimum model size and RAM.
- Kept the initial classes simple: weed and crop/plant.
- Designed the workflow around training once, then exporting to a target-specific local runtime such as ONNX, NCNN, TFLite, OpenVINO, or TensorRT.

Problems encountered:
- There was no existing codebase to modify.
- There was no dataset yet, so training could not be run during this iteration.

Fixes attempted:
- Created a complete starter pipeline instead of only writing a recommendation.
- Added clear dataset folder expectations and commands for training/export.

Results and observations:
- The scaffold compiled successfully with py_compile.
- The project now had a concrete path from labeled images to local edge inference.

Next steps:
- Install dependencies.
- Add labeled weed/crop images in YOLO format.
- Validate dataset labels before training.
- Train the first nano detector.

Iteration 011 - Public Dataset Scout For Better Stage 1 Data
Date: 2026-05-24

What was done:
- Looked for public crop/weed detection datasets that could improve Stage 1 field weed detection.
- Focused on datasets with bounding boxes, real field imagery, and crop/weed relevance.

Why it was done:
- Current Stage 1 detector is improved but still not high-accuracy enough.
- Better or complementary data may improve recall and box quality, especially for small weeds.

Thought process and reasoning:
- Prioritized datasets with object detection annotations over classification-only datasets.
- Treated domain match as the key issue: a dataset is only better if its crop type, camera angle, plant scale, field conditions, and annotation style are close to the rover target.
- Considered classification datasets useful for Stage 2, but not sufficient for Stage 1 detector improvement.

Problems encountered:
- Many weed datasets are classification-only or segmentation-focused, not YOLO-style bounding-box detection.
- Public datasets often target different crops, countries, camera heights, UAV views, or weed species.
- Adding mismatched data can improve generic robustness but may hurt rover-specific accuracy if mixed carelessly.

Fixes attempted:
- Grouped candidate datasets by practical use:
  - Stage 1 detection augmentation
  - Stage 2 species classification
  - possible future segmentation/reference data

Results and observations:
- Strong Stage 1 detection candidates:
  - CropAndWeed dataset: about 8k high-resolution images and about 112k annotated plant instances, with bounding boxes, masks, and stem positions for 74 crop/weed species.
  - Crop and Weed Detection Data with Bounding Boxes: 1300 YOLO-format 512x512 field images for sesame crop and weeds.
  - WeedCrop dataset mentioned in recent literature: 2822 RGB images with YOLO-format bounding boxes.
  - Newer cotton-field weed/crop YOLO datasets exist, but crop/camera domain may differ.
- Stage 2 classification candidates:
  - DeepWeeds: 17509 images, 8 weed species plus negative/off-target plant life.
  - Agro_Dataset_344k: large aggregated classification-style dataset made from many public weed/plant datasets.
- Best immediate external dataset to investigate for Stage 1 is CropAndWeed, followed by the 1300-image crop/weed bounding-box dataset.

Next steps:
- Do not blindly mix external datasets into MH-16 training.
